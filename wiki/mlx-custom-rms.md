# 自定义 Metal RMSNorm：双输出与非连续输入的成本

证据：2026-10-07，M4/MLX 0.31.2 的限定观测。三条路径的 **216 项预检查和 1512 个计时样本均通过原定数值门**。自定义融合候选在不同 dtype、尺寸和布局下表现不同；默认连续化的复制成本必须保留在比较中。本页没有 GPU 时间戳、profiler、实际 dispatch 数或模型收益证据。

## 先改变输出契约，再比较候选

本轮同时返回 `y=RMSNorm(s,w,eps)` 与 `s=x+r`，s 在输入 dtype 舍入。原生基线只构造一次 s，并将同一个 s 交给 `mx.fast.rms_norm`，最后共同求值 y/s。它与[上轮仅返回 y 的比较](mlx-residual-rms.md)不同，旧时间不能直接当成本轮基线。所读 [v0.31.2 normalization.cpp](https://github.com/ml-explore/mlx/blob/v0.31.2/mlx/backend/metal/normalization.cpp) 对可捐赠输入有缓冲复用分支；保留 s 可能改变分配，尚未测量本轮实际 donation。

两个原创自定义候选使用相同算法：每行 256 个线程，每线程保留 16 或 17 个 T 类型 residual 值；先写满 s 并以 float 累加平方，SIMD 内归约后，各 leader 写 threadgroup partial。第一次 barrier 后由 thread0 按运行时 SIMD 组数累加并计算 `precise::rsqrt`，第二次 barrier 后写 y。归一化先转回 T，再乘同 dtype 的 W 并写回 T。局部缓存可能增加寄存器压力；本轮未测 spill 或占用率。

partial 预留 256 个 float，不将 SIMD 宽度固定为 32。D4103 的最后 7 个元素参与加法、归约和两个输出；无效列只屏蔽访问，所有线程仍执行 barrier。网格为 `(256,M,1)`，线程组为 `(256,1,1)`，行号取 threadgroup y 坐标。这个 grid 表示线程总数，不能误传为线程组数量。[版本固定的 API 指南](https://github.com/ml-explore/mlx/blob/v0.31.2/docs/src/dev/custom_metal_kernels.rst)

## 连续化与 stride 寻址是两条路径

- `fast`：上述原生双输出基线。
- `custom_copy`：`ensure_row_contiguous=True`，kernel 用平面索引；框架需要时先复制输入。
- `custom_strided`：`ensure_row_contiguous=False`，分别按 X、R 的两个 strides 和 W 的一个 stride 寻址。

[v0.31.2 custom-kernel 实现](https://github.com/ml-explore/mlx/blob/v0.31.2/mlx/backend/metal/custom_kernel.cpp) 在 source 用到对应名字时注入 shape/stride 元数据；stride 类型为 int64。默认连续化发生在实际求值内，本轮没有在计时前调用 contiguous。输出逐元素写满，未指定 `init_value` 或 atomic outputs。一次 custom API 调用不能证明整条路径只有一次 dispatch，尤其是需要复制输入时。

每个 dtype/shape 的连续与隔列输入逻辑值相同。隔列输入先建立完整 MLX backing，再取 `[...,::2]`；空隙分别填 7/8/9，不把 NumPy 非连续 view 直接上传来冒充 GPU 非连续输入。独立诊断 kernel 读取实际元数据：隔列 X/R 的列 stride 及 W stride 均为 2，连续对照均为 1；实际输入还逐元素回读对照保存值。诊断在候选计时外，不等于 profiler。

本机 0.31.2 的接口与保留的 docstring 没有新版 `compile_options` 参数，本轮未使用它；不能照搬[当前文档](https://ml-explore.github.io/mlx/build/html/dev/custom_metal_kernels.html)中 0.32.3 的 math-mode 调用示例。

## 数值验证覆盖

Apple M4/16GB，macOS 27.0（26A428），MLX 0.31.2、Python 3.14.3、NumPy 2.4.3。默认 Metal GPU，精度环境变量未设置；未安装或更新软件包。X/R/W 同 dtype，float32/BF16，M={1,32,512}、D={4096,4103}、`eps=float32(1e-5)`。所有输入为有限值。

CPU PCG64 seed=47，为每个 D 顺序生成 X=normal、R=0.25×normal，W=`1+0.125*sin(channel)`。三个分布是随机、放大 64 倍，以及相消：R=-X，奇数行再加 1/64，偶数行给出全零 residual。存储舍入后奇数行不保证恒等于 1/64。小 M 是同一最大输入的前缀；同 seed、布局与进程重复不能算独立随机样本。

CPU 从实际存储输入开始，将 X+R 按输入 dtype 舍入得到 s，再以 float64 归约、归一化并乘 W 得到 y 参考。s 必须精确相等；y 的 F32 最大绝对误差和最大逐行 relative L2 均 ≤1e-5，BF16 分别 ≤0.0625、0.008；零参考行要求精确为零，另检查 shape/dtype/有限性。没有改变门槛或用原生输出替换 CPU oracle。

| dtype / 路径 | 最大绝对误差 | 最大逐行 relative L2 |
|---|---:|---:|
| F32 / fast | 7.07e-7 | 1.13e-7 |
| F32 / 两个 custom 各自 | 7.37e-7 | 1.21e-7 |
| BF16 / 三路各自 | 0.03093 | 0.002929 |

216 项均通过，全部 s 精确相等。独立 NumPy CPU 复核对保存的 216 对预检查及 108 对 first 输出重新计算原门，全部通过；72 组两个 custom 的 y/s 对照、108 组连续/隔列对照均逐元素一致，108 对 first 也均与对应预检查相同。该相等关系仅限这些保存输入。D4103 属于正确性覆盖，下面没有尾维性能结论。这些门是合成任务目标，不是模型质量或框架逐位等价保证。

## 双输出主机完成时间

仅在全部 216 项预检查通过后，协调器才启动 9 个 benchmark 进程，每路径 3 个进程；逐轮轮换路径顺序，进程内轮换 dtype/M/layout 的起始条件。性能只测随机分布、D4096。每条件 1 次 first、3 次 warmup、10 次预热后样本，共 108/324/1080 个；全部 1512 项的 y/s 在线检查通过。

输入和 kernel 对象在计时前准备并复用；每次同步默认 stream，再从新函数调用计到 `mx.eval(y,s)` 完成，包含需要的自动连续化。CPU 回读、验证和保存位于区间外，但会影响下一次状态；未控制其他应用、温度、功耗或系统缓存，未刷新缓存。不同 M/layout 可以复用同一已编译 kernel，first 不是独立冷编译时间，也不是纯编译耗时。

F32/M512 连续输入的三轮均是两个 custom 比 fast 快。M512 隔列时，两种 dtype 三轮均为 `custom_strided < fast < custom_copy`；但 BF16 的 fast/strided 比仅 1.011–1.014，进程中位数范围重叠，只是本次小幅观察差异。BF16/M512 连续时 custom_copy 两轮快、一轮慢；BF16/M1 连续则三轮均为 fast 最快。小 M 没有统一赢家，不能仅凭汇总中位数选路线。

`custom_copy` 的连续与隔列差值是完整路径的差值，不能称为纯复制耗时；strided 还改变了寻址指令。本轮支持继续验证复制与寻址的取舍，不支持无条件关闭连续化或全模型替换。

## 采用与复验边界

在实际模型中先确认此双输出确为热点，再按真实 dtype、W 类型、输出存活期、布局与容差验证。关闭连续化之后，kernel 必须为每个输入正确寻址；本轮只测共同隔列步长 2，没有验证转置、负 stride、广播、X/R/W 彼此不同的步长或任意 shape。未测 FP16、混合 dtype、NaN/Inf、完整动态范围、反向传播、其他芯片、模型或服务。

原始运行正常退出，保存执行脚本、生成的自定义源码、环境、输入/CPU 参考、216 对预检查输出、108 对 first 输出，以及全部计时与检查指标。其余成功样本只保存在线指标，不能声称后续独立重算了全部 1512 对输出。来源 `local-mlx-custom-rms-20261007`，逻辑引用 `2026-10-07-mlx-custom-rms/derived/summary.json`；原始记录在仓库外、未随公开库发布，外部读者不能仅凭本页独立复验原运行。
