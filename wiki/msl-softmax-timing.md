# MSL softmax 计时：线程分工、分块与实际调用成本

[English companion](en/msl-softmax-timing.md)

减少源码中的输入遍历、扩大线程组、把长行拆成多个 kernel，都会同时改变别的成本。本页对[已通过数值门的六种 softmax 路线](msl-softmax.md)做有限的 M4 主机完成计时，帮助选择下一步候选。它测量给定 logits 到概率的调用序列，没有 QK/PV、KV cache、完整 attention 或模型推理。

## 同一输入与同一计时边界

2026-10-07，Apple M4/16GB、macOS27.0（26A428）、MLX0.31.2、NumPy2.4.3、Python3.14.3，`MLX_ENABLE_TF32` 未设置。复用数值运行保存的 F32 logits 和 uint32 mask：R=8，K=128/257/8193；两种布局为连续和 x/mask 均 step2。八行混合了 uniform、全 mask、单有效项、prefix、首末有效、尖峰及随机平移对照，**不是 dense-only attention 或真实模型分布**。

原始八份 MSL 函数体未改，仅 JIT wrapper 更名。SG32 precise/fast 是三遍读取，TG128 跨四个 SIMD-group 归约，online32 在线统计后重读输出，split256 依次计算块状态、全行状态、最终概率；native 是显式 `where(mask,x,-16385)` → `softmax(precise=True)` → `where(mask,p,0)`。空行正零及有限输入域沿用原合同。

每个样本使用如下边界：

```python
mx.synchronize()                  # 默认 GPU stream，计时窗外
t0 = time.perf_counter_ns()
y = call_route(x, mask)            # 每次重新构图
mx.eval(y)
elapsed_ns = time.perf_counter_ns() - t0
saved = np.array(y)                # 读回、检查与保存均在窗外
del y
```

计入 Python 构图、分配、编码、GPU 工作和等待；native 的 mask 包装与 split 的全部三个阶段及中间依赖都在窗内。输入/view 准备、metadata 检查、wrapper 对象创建不在窗内。上一调用返回的 GPU y 不跨样本保留，但路线内部的临时数组与分配器缓存仍可存在，不能据此断言峰值内存相同。

每次调用后读回并检查，六条路线完成一个 block 后统一压缩保存 CPU 数组；读回和检查发生在样本间，文件写入发生在 block 间。因此它是**带逐次验证的主机完成时间**，不是连续 GPU 吞吐或纯 kernel 时间。没有 profiler、缓存清空、温度/功耗控制，背景活动也未隔离。

## 预定顺序与独立复核

三个进程依次执行，只有前一进程退出0且 terminal 完整通过才继续。每条件、每路线、每进程保留1次first、2次warmup、12次timed；每个block六路线交错，12个timed block让每路线在六个位置各出现两次。奇数进程反转基础路线次序，条件次序轮转。此安排不能消除前一调用、cache或热状态影响。

first 指该进程内该路线/条件的首次调用，不代表全系统冷 JIT 或冷缓存。计时统计只使用timed，first/warmup另存。跨进程汇总先求每进程12个值的中位数，再报三个中位数的中位数与最小/最大值；没有将36个值视作36次独立进程复制，也不报告p95或显著性。

三个进程均退出0，保存全部1620份最终输出（108 first、216 warmup、1296 timed）和36项metadata。独立CPU审查用保存F32输入重新计算 `math.exp`/`math.fsum` oracle，核对逐元素混合门、行和、行L1、finite/非负、masked正零和平移关系；所有输出通过，事件指标一致。最大概率绝对误差约2.417639e-8，最大误差/逐元素容差约0.00250303，最大行和误差约1.206154e-7。原函数体和所选输入与前一记录直接核对一致，准确执行顺序、输出索引和正整数host_ns也通过检查。

同一条件/路线的重复调用及三个进程输出均与其p0 first输出逐位相同，1620项平移对照也逐位相同；这些仅为本批记录的诊断。审查器初版误要求原输入NPZ仅含三个字段，因额外保存的合法行统计而退出2；修正字段检查后重新审查，初版源码与报告另存，原GPU记录未改、未补跑。审查保存数组不能独立证明历史物理stride、隐藏访存或执行时的计时边界。

## 怎样应用到 MSL 优化

- **按行宽保留结构不同的候选。** 单 SIMD 的简单归约、跨 SIMD 的共享归约、跨 kernel 的分块合并不能仅按“launch 少”或“线程多”预先排除。应在目标行数、宽度、mask与输出使用方式下比较完整代价。
- **在线算法是读取与算术的交换。** 少一次源码读取，同时增加重缩放指数和串行状态依赖；这两个事实不决定最终速度。要区分在线softmax自身与完整attention避免物化分数矩阵的收益。
- **函数命名空间与质量、时间分别验证。** `fast::exp` 与 `precise::exp` 的源码差别不是整 kernel 加速承诺；MLX API `precise=True` 也不是选择 MSL `precise::exp` 的证据。
- **wrapper也是部署调用的一部分。** native 的额外mask表达式可能生成中间数组，split需要中间状态；本测量把这些工作计入。不能把 native/custom 的 step2时间差解释为同一个softmax kernel在相同物理布局上的差异。
- **从目标工作负载继续收窄。** 本页只提供候选选择线索；改变R、K、dtype、mask密度、并发或融合边界后，需要相应数值门和实际时间。主机耗时不能说明寄存器、DRAM、指数指令或同步中哪一个是瓶颈。
